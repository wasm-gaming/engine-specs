## 1. i18n

- `type Locale = 'en' | 'es'`; `LOCALES`.
- `type Localized = string | { en: string; es?: string }`. A plain string is English.
- `localize(text: Localized, locale: Locale): string`, falling back to `en`.
- `resolveLocale(preferred?: string): Locale`. It takes the host's locale, else the first of
  `navigator.languages` that is supported (matched on the primary subtag, so `es-419` is `es`),
  else `en`.
- `EngineAppHost.locale?: Locale`: the launcher passes its own; an app without it calls
  `resolveLocale()`.
- The strings engine-specs itself shows get an `{ en, es }` table: the settings screen, the
  controls capture, the reset confirm, the counter.
- SDK error messages stay English (they are for developers).

## 2. Settings

**Contract**: `PropertyDefinition` gets optional fields. The same fields go on `PropertySpec`,
since it is `Omit<PropertyDefinition, 'value'>`.
- `label?: Localized`. A property with a `label` is a player-facing setting; one without stays
  internal.
- `group?: 'video' | 'audio' | 'emulation' | 'game' | 'controls'`: the screen's sections, in that
  order.
- `valueLabels?: Localized[]`: the names of the `enum` values, in the same order.
- `live` keeps its meaning. A setting that is not live shows "Applies on restart" /
  "Se aplica al reiniciar".

**The model** (pure, tested without a browser):
- `settingsModel(described, values, locale)`:
  - input: the `config()` / `options()` descriptors and the saved values;
  - output: groups → rows (`key`, `label`, `value`, `valueLabel`, `live`, `description`).
- `stepSetting(row, +1 | -1)`: enums cycle; booleans toggle (Yes / No, "Sí" / "No"); numeric enums
  (volume) step without wrapping.
- `settingsDefaults(described)`, for the reset.

**Storage**: `loadSettings(engineId)` / `saveSettings(engineId, values)`.
- OPFS `settings/<engineId>.json`, per engine, shared by all its games (the owner's decision 1).
- JSON `{ version: 1, values: {…}, controls: {…} }`.
- A missing or broken file reads as "no saved settings", never as an error.

**The screen**: `createSettingsScreen(target, { model, input, locale, onChange, onClose })`.
- DOM, styled with `UI_TOKENS`, and following UX.md:
  - one row is always focused;
  - `up` / `down` move between rows;
  - `left` / `right` / `accept` change the value;
  - `more` shows the description;
  - `back` closes;
  - a tap cycles a row on touch.
- `onChange(key, value, live)` lets the app apply a live setting at once. The app saves either way
  (the helper does not touch the engine).
- A last row, "Reset to defaults" / "Restablecer", asks first, defaulting to No (rule 6).
- **UX.md** gets a "Settings" section with these rules. Rule 4's pause menu becomes: Continue, the
  engine's own entries, **Settings**, Exit.

## 3. Controls (remapping)

- `ControlBinding = { key?: string; button?: number }` per engine button. The engine's button list
  (`{ id, label: Localized }[]`) comes from the app.
- `controlsModel(buttons, defaults, saved)`: rows for the "Controls" group, each showing its key
  and its gamepad button (with the glyph names from UX.md rule 9).
- `captureBinding(input, { signal })`: resolves with the next key or button press. Escape cancels
  (it resolves `undefined`). The shared input is suspended meanwhile, so the capture does not also
  move the focus.
- A key already used by another button is swapped with it, never duplicated.
- Saved under `controls` in the same settings file; "Reset" restores the defaults.
- How a binding reaches the game is each engine's business (its own mapping, or the SDK's). Its
  record says which.

## 4. Fullscreen

- `createFullscreenToggle(root, input, options?)`. `toggle()` calls `requestFullscreen()` /
  `exitFullscreen()` on the app's root.
- Keyboard:
  - **Cmd+Enter on macOS, Alt+Enter on Windows / Linux** (the owner's choice), remappable;
  - the platform is read from `navigator.userAgentData?.platform`, else `navigator.platform`;
  - ignored while a text field has focus.
- Gamepad: **Select + Y** (button 8 + 3). This is still the owner's to confirm (see the questions
  below). Select + Start stays the menu combo.
- Also a pause-menu entry, since some browsers accept only a pointer or key gesture for fullscreen.
- `isFullscreenKey(event, platform)` is pure and tested.

## 5. Performance

- **Wake Lock**: `createWakeLock()`.
  - It is held while playing, and released on pause and when the page is hidden.
  - It is taken again on `visibilitychange` back to visible.
  - Without the API, it does nothing.
  - Setting: Video → "Keep the screen on" / "Mantener la pantalla encendida" (default on).
- **Counter**: `createPerfCounter(target)`, a small overlay.
  - It shows FPS, frame time (average and worst over the last second) and dropped frames.
  - Engines feed it with `frame()` once per emulated frame; it does its own `rAF` sampling as a
    fallback.
  - Setting: Video → "Show performance" / "Mostrar rendimiento".
- **Audio-paced loop**: `createFrameClock({ fps, mode: 'display' | 'audio', audioContext? })`.
  - It calls `tick(n)` with the number of frames due. In `audio` mode they are counted from
    `audioContext.currentTime`, so a 120 Hz screen or a skipped `rAF` does not change the speed.
  - The maths is pure and tested (`framesDue(elapsed, fps, carried)`).
  - Setting: Emulation → "Sync: audio / display" / "Sincronización: audio / pantalla". Only the
    engines whose loop the SDK drives use it; their records say so.
- **The Worker + `OffscreenCanvas` option is not in engine-specs**: it depends on each engine's
  build, and comes per engine after the screen ships.

## Walkthrough (2026-11-17 13:30 UTC) — 0.6.0 built

Adds: what was built, the two changes beyond the plan, and the checks.

**Contract** (all optional, nothing existing changes shape):
- `PropertyDefinition` gets `label?: Localized`, `group?: SettingGroup` and
  `valueLabels?: Localized[]`. `PropertySpec` gets them too.
- `EngineAppHost.locale?: Locale`.

**New in `src/engine-specs.ts`**, in one section at the end:
- **Languages**: `LOCALES`, `Locale`, `Localized`, `localize()`, `resolveLocale(preferred,
  languages)`, `UI_STRINGS` (en / es) and `uiText()`.
- **Settings**:
  - the model: `SETTING_GROUPS`, `settingsModel()`, `stepSetting()`, `withSettingValue()`,
    `settingsDefaults()`;
  - the shared settings: `SHARED_SETTINGS` (`keepScreenOn` on by default, `showPerformance`) and
    `FRAME_SYNC_SETTING` (`frameSync`: display / audio);
  - storage: `parseSettings()`, `loadSettings()` / `saveSettings()` (OPFS
    `settings/<engineId>.json`; the engine id is validated);
  - the screen: `createSettingsScreen()`.
- **Controls**: `ControlButton` / `ControlBinding`, `PAD_BUTTON_NAMES`, `keyLabel()`,
  `controlsModel()`, `bindControl()` (it swaps, never duplicates) and `captureBinding()`.
  `onControl(id, binding, bindings)` hands the app every binding after the swap, which is what it
  saves.
- **Fullscreen**: `platformOf()`, `fullscreenShortcut()` (Cmd+Enter / Alt+Enter), `isShortcut()`,
  `FULLSCREEN_PAD_COMBO` (Select + Y) and `createFullscreenToggle()`.
- **Performance**: `createWakeLock()`, `frameStats()`, `createPerfCounter()`, `framesDue()` and
  `createFrameClock()` (display / audio clock, the backlog capped at 4 frames after a stall).

**Two changes to `createInput()`**, found while checking in Chromium:
- **`UiInput.mute()`** (optional on the type; `createInput` always has it) silences everything,
  the menu combo included. `captureBinding()` uses it. Without it, the Escape that cancels a capture
  also reached the input first, since it listens earlier on the window, and opened the pause menu.
- **Y is quiet while Select is held**, and until Y is let go. Select + Y is fullscreen, so in a
  menu it no longer also fires `more`. This follows the Select + Start rule.

**UX.md**:
- rule 4's pause menu becomes Continue, the engine's entries, **Settings**, **Fullscreen**, Exit;
- new sections: Languages, Settings, Controls and Fullscreen.

**Demo**: `demo/settings.html`, linked from the toolbar.
